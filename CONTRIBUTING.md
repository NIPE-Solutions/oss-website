# Contributing

Thank you for helping maintain NIPE Open Source. By participating, follow the
[Code of Conduct](CODE_OF_CONDUCT.md).

## Before opening a pull request

1. Discuss material content, design, or deployment changes in an issue first.
2. Keep a change focused and preserve the static-site and registry-first
   architecture.
3. Run `npm run check`; run `npm run test:e2e` when a user-facing route,
   interaction, or layout changes.
4. Describe the evidence used for changed public claims and the verification
   you ran.

## Project and legal content

Follow [`docs/ADDING_A_PROJECT.md`](docs/ADDING_A_PROJECT.md) for all
directory changes. A legal-source update must identify the current canonical
source and the processing it describes; do not copy wording from another NIPE
site without confirming that it applies here. Legal, privacy, security-policy,
and deployment-domain changes require owner review before merge or publication.

## Review and merge

Maintainers review changes for evidence, accessibility, privacy impact, and
scope. Do not merge your own change unless you are the authorized owner and
have completed the required review.
